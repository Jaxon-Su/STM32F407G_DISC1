STM32 HAL Example 004 呼叫關係筆記
===================================

目前專案目標：
用 HAL/CubeMX 搬移課程中的 SPI command/response demo。
STM32F407G-DISC1 當 SPI2 Master，Arduino 或另一個 MCU 當 SPI Slave。

這個案例需要 slave 端韌體配合，slave 收到 command 後要回 ACK 0xF5。
目前如果沒有 Arduino，程式仍可 build/flash，但大多數 command 會因為收不到 ACK 而顯示失敗。

1. main.c
---------
main.c 是 CubeMX 產生的入口。

啟動流程：
- HAL_Init()
- SystemClock_Config()
- MX_GPIO_Init()
- MX_SPI2_Init()
- Example004_SpiCmdArduinoSlave_Init()
- while(1) 裡呼叫 Example004_SpiCmdArduinoSlave_Loop()

2. example_004_spi_cmd_arduino_slave.c
--------------------------------------
這是案例 004 的主要邏輯。

每按一次 PA0/B1，執行下一個 command：
- COMMAND_LED_CTRL    0x50
- COMMAND_SENSOR_READ 0x51
- COMMAND_LED_READ    0x52
- COMMAND_PRINT       0x53
- COMMAND_ID_READ     0x54

執行完 5 個 command 後回到第一個 command。

LED 顯示：
- LD4 toggle：本次 command 成功
- LD5 toggle：本次 command 失敗，常見原因是沒有收到 ACK 0xF5
- LD6 toggle：一輪 5 個 command 結束

3. SPI2 腳位
------------
- PB12 -> SPI2_NSS
- PB13 -> SPI2_SCK
- PB14 -> SPI2_MISO
- PB15 -> SPI2_MOSI
- PA0  -> B1 Blue PushButton

若接 Arduino UNO：
- STM32 PB13 SCK  -> Arduino D13 SCK
- STM32 PB15 MOSI -> Arduino D11 MOSI
- STM32 PB14 MISO <- Arduino D12 MISO，需要 level shifting 或保護
- STM32 PB12 NSS  -> Arduino D10 SS
- STM32 GND       -> Arduino GND

注意：STM32F407 是 3.3V，Arduino UNO 常見是 5V。
Arduino D12/MISO 若輸出 5V 到 STM32 PB14，會有風險。雙向 SPI 建議使用 level shifter。

4. SPI 設定
-----------
- SPI2 Master
- Full duplex
- CPOL low
- CPHA first edge
- SPI Mode 0
- Hardware NSS output
- Prescaler /32
- MSB first

5. HAL 對應課程 driver-layer 概念
--------------------------------
課程原本：
- SPI_SendData() 送 command / dummy byte / args
- SPI_ReceiveData() 讀 dummy read / ack / data

HAL 版本：
- HAL_SPI_TransmitReceive() 同時送 1 byte 並收 1 byte
- Example004_SendByteIgnoreRx() 用來送 command 或 args，收到的 byte 丟掉
- Example004_TransferByte(DUMMY_BYTE, &rx) 用 dummy byte 換回 slave 的 ack/data

SPI 是 full-duplex：
每送出 1 byte，同時也會收到 1 byte。
所以讀 slave 資料時，master 必須送 dummy byte 來產生 SCK。

6. ACK 流程
-----------
每個 command 大致流程：
- Master 送 command code
- Master 送 dummy byte 產生 clock
- Slave 回 ACK 0xF5
- 若 ACK 正確，Master 再送 arguments 或讀資料

7. 沒有 Arduino 時如何理解
--------------------------
沒有 slave 時，MISO 沒有人正確回 ACK。
因此程式通常會走到失敗路徑，LD5 toggle。

這不是 SPI 設定壞掉，而是因為案例 004 本質是 master/slave protocol，需要另一端裝置配合。
要真正驗證：
- 接 Arduino 並燒錄對應 slave 程式，或
- 用另一塊 MCU 當 slave，或
- 用邏輯分析儀觀察 PB12/PB13/PB15/PB14 波形。
