STM32 HAL Example Note
======================

案例：013 UART TX RX Interrupt
來源概念：016uart_case.c

目標
----
這個案例練習 UART receive interrupt。

按下 `B1 / PA0` 後，STM32 選一段訊息送出，並同時用 interrupt 等待收到同長度資料。

三段訊息輪流送：

```c
"hihihihihihi123"
"Hello How are you ?"
"Today is Monday !"
```

程式先啟動 RX interrupt，再送 TX：

```c
HAL_UART_Receive_IT(&huart2, rx_buf, len);
HAL_UART_Transmit(&huart2, msg, len, 100);
```

這代表 RX 是 interrupt，TX 仍然是 polling/blocking。

硬體設定
--------

- `PA2`：USART2_TX
- `PA3`：USART2_RX
- Baud rate：`115200`
- Format：8N1
- `PD12 / LD4`：收完預期長度資料後 toggle
- `PD14 / LD5`：UART error 或啟動失敗時 toggle

測試方式：

```text
STM32 PA2 TX -> 外部裝置 RX
STM32 PA3 RX <- 外部裝置 TX
GND          -> GND
```

如果要做 loopback 測試，也可以暫時把 `PA2` 接到 `PA3`，讓 STM32 自己送出的資料回到自己 RX。

main.c 的角色
-------------

初始化：

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_USART2_UART_Init();
Example013_UartTxRxIt_Init();
```

主循環：

```c
while (1)
{
    Example013_UartTxRxIt_Loop();
}
```

USART2 的 GPIO / clock / NVIC 在 `HAL_UART_MspInit()` 設定：

```c
__HAL_RCC_USART2_CLK_ENABLE();
GPIO_InitStruct.Pin = GPIO_PIN_2 | GPIO_PIN_3;
GPIO_InitStruct.Alternate = GPIO_AF7_USART2;
HAL_NVIC_EnableIRQ(USART2_IRQn);
```

中斷入口
--------

UART RX interrupt 完成時，CPU 會進：

```c
void USART2_IRQHandler(void)
{
    HAL_UART_IRQHandler(&huart2);
}
```

然後 HAL 內部檢查 USART2 flag，接收滿指定長度後呼叫：

```c
HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
```

本案例實作：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        rx_complete = 1;
    }
}
```

所以 callback 本身沒有處理字串，只是通知 main loop：「收完了」。

為什麼先 Receive_IT 再 Transmit
------------------------------

程式順序是：

```c
rx_complete = 0;
HAL_UART_Receive_IT(&huart2, rx_buf, len);
HAL_UART_Transmit(&huart2, msg, len, 100);
while (!rx_complete) {}
```

先開 RX 的理由是避免資料太快回來時漏接。

如果先 transmit，再 receive，外部裝置可能已經回傳資料，但 STM32 RX interrupt 還沒啟動，就會錯過一部分 byte。

rx_complete 的角色
------------------

`rx_complete` 是 main loop 和 callback 之間的旗標：

```c
static volatile uint8_t rx_complete;
```

需要 `volatile`，因為它會在 interrupt callback 裡被修改，也會在 main loop 裡被讀取。

如果沒有 `volatile`，編譯器可能以為 `rx_complete` 不會突然改變，導致 while loop 判斷被最佳化得不符合預期。

本案例的等待方式
----------------

```c
while (!rx_complete) {}
```

這是 busy wait，學習上很直覺，但實務上通常會避免長時間空轉。

更完整的寫法會加 timeout，例如：

```text
啟動 Receive_IT
記錄 start tick
while 還沒完成
  檢查是否 timeout
```

但本案例保留簡單形式，方便專注在 callback 流程。

callback 呼叫路徑
----------------

```text
Example013_Loop()
  -> HAL_UART_Receive_IT()
  -> UART RX hardware 開始接收
  -> 收滿 len bytes
  -> USART2_IRQHandler()
  -> HAL_UART_IRQHandler(&huart2)
  -> HAL_UART_RxCpltCallback()
  -> rx_complete = 1
  -> while (!rx_complete) 結束
  -> LD4 toggle
```

錯誤處理
--------

如果 UART 發生 error，例如 framing error、overrun error，HAL 會呼叫：

```c
HAL_UART_ErrorCallback()
```

本案例：

```c
rx_complete = 1;
HAL_GPIO_TogglePin(LD5_GPIO_Port, LD5_Pin);
```

把 `rx_complete` 設成 1 是為了讓 busy wait 可以跳出，不會永遠卡住。

學習重點
--------

013 的重點不是單純收字串，而是理解：

```text
IT API 只是啟動接收
真正完成通知在 callback
callback 改 flag
main loop 根據 flag 做後續處理
```

這個模式和 I2C/SPI interrupt 很像。
